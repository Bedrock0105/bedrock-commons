# 日志模块 (Log)

## 概述

`bedrock-common-log` 提供两类日志能力：

1. **操作日志**：通过 `@OperationLog` 注解 + AOP 自动记录业务操作，支持 SpEL 模板与持久化
2. **请求日志**：自动拦截 `@RestController` / `@Controller` 接口，打印请求/响应详情
3. **链路追踪**：`LogTraceFilter` 自动生成 TraceId 写入 MDC

操作日志持久化依赖 `bedrock-log` 微服务：业务服务通过 Feign 调用 `ILogSaveFeign` 保存到数据库。

---

## 快速开始

### 1. 引入依赖

微服务项目通过 `bedrock-common-cloud` → `bedrock-common-boot` 间接引入，无需单独添加。

如需单独使用：

```xml
<dependency>
    <groupId>org.bedrock</groupId>
    <artifactId>bedrock-common-log</artifactId>
</dependency>
```

### 2. 启用日志持久化

业务服务需能 Feign 调用 `bedrock-log` 服务（`ILogSaveFeign` 已内置）。`bedrock-log` 模块实现 `LogSaveClient` 接收并入库。

### 3. 在 Controller 上使用操作日志

参考 `bedrock-cloud` 中 `AdminController` 的写法：

```java
@PostMapping("/submit")
@OperationLog(
    type = "管理员管理",
    subType = "添加管理员",
    success = "新增管理员 username: {{#param.username}}",
    extra = "{TO_JSON{#param}}",
    condition = "{{#_errorMsg == null}}"
)
public R<Void> submit(@RequestBody AdminSubmitParam param) {
    return R.status(adminService.submit(param));
}
```

## @OperationLog 注解

标注在**方法**上，由 `OperationLogAspect` 拦截。

| 属性 | 必填 | 说明 |
|------|------|------|
| `type` | 是 | 一级分类，如「管理员管理」 |
| `subType` | 否 | 二级分类，如「添加管理员」 |
| `success` | 是 | 成功时的日志模板（SpEL） |
| `fail` | 否 | 失败时的日志模板，为空则不记录失败日志 |
| `extra` | 否 | 额外信息 |
| `condition` | 否 | 记录条件，SpEL 返回 boolean，`true` 才记录 |

支持 `@Repeatable`，同一方法可叠加多个 `@OperationLog`（通过 `@OperationLogs` 容器）。

### SpEL 语法规则

1. 表达式用 `{{ }}` 包裹，如 `{{#param.username}}`
2. 内置变量：
   - `#_ret`：方法返回值
   - `#_errorMsg`：方法抛出的异常（失败场景）
   - `#_oldValue`：差异对比时的旧值
3. 方法参数直接引用：`{{#id}}`、`{{#param.xxx}}`
4. 自定义函数：`{functionName{变量}}`，如 `{TO_JSON{#param}}`
5. 差异对比：`{_DIFF{#newValue,#oldValue}}` 或 `{_DIFF{#newValue}}`

### 内置解析函数

| 函数名 | 说明 |
|--------|------|
| `TO_JSON` | 将对象序列化为 JSON 字符串 |
| `_DIFF` | 对比新旧对象差异，需配合 `@DiffLogField` |

### 记录条件示例

仅在操作成功时记录（`R.status()` 返回失败时不抛异常，需结合业务判断）：

```java
condition = "{{#_errorMsg == null}}"
```

## LogRecordContext 上下文变量

当 SpEL 模板需要的变量无法从方法参数直接获取时，在 Service 层手动注入：

```java
// AdminServiceImpl.removeById
Admin admin = this.getById(id);
LogRecordContext.putVariable("username", admin.getUsername());
return logicRemoveById(id);
```

Controller 注解中即可使用 `{{#username}}`。

## 差异对比日志

在实体字段上标注 `@DiffLogField`：

```java
public class Admin {
    @DiffLogField(name = "用户名")
    private String username;

    @DiffLogField(name = "状态", dict = "{\"1\":\"启用\",\"0\":\"禁用\"}")
    private Integer status;
}
```

Service 中保存旧值：

```java
LogRecordContext.putVariable("_oldValue", oldAdmin);
LogRecordContext.putVariable("admin", newAdmin);
```

模板中使用：

```java
success = "修改管理员 {_DIFF{#admin}}"
```

## 自定义解析函数

实现 `IParseFunction` 并注册为 Spring Bean，启动后自动注册：

```java
@Component
public class DeptNameParseFunction implements IParseFunction {
    @Override
    public String functionName() {
        return "DEPT_NAME";
    }
    @Override
    public String apply(Object value) {
        // 根据 deptId 查询部门名称
        return deptService.getNameById((Long) value);
    }
}
```

模板：`{DEPT_NAME{#param.deptId}}`

差异对比函数实现 `IDeffParseFunction`，函数名以 `_DIFF` 开头。

## 请求日志

`RequestLogAspect` 自动拦截所有返回 `R` 的 Controller 方法，打印请求/响应详情。

### 配置（bedrock.log.request.*）

```yaml
bedrock:
  log:
    request:
      enabled: true              # 是否启用，默认 true
      level: INFO                # 日志级别：TRACE/DEBUG/INFO/WARN/ERROR/OFF
      max-length: 2147483647     # 单行最大长度
      exclude:                   # 不打印日志的 URL（Ant 风格）
        - /actuator/**
      excluded-handlers: []      # 脱敏的请求头
      handlers-log: true         # 是否打印请求头
      method-params-log: true    # 是否打印方法参数
      method-return-log: true    # 是否打印响应
      method-return-msg-log: true # 是否打印响应数据
```

### 排除某个接口

```java
@ExcludeRequestLog
@GetMapping("/health")
public R<String> health() { ... }
```

### 方法级自定义

```java
@RequestLogConfig(level = LogProperties.LogLevel.DEBUG, methodReturnMsgLog = false)
public R<List<User>> list() { ... }
```

## 链路追踪

`LogTraceFilter` 自动为每个请求生成 TraceId 并写入 MDC，logback 配置中可通过 `%X{traceId}` 输出。

---

## 持久化流程

```
Controller @OperationLog
    → OperationLogAspect
    → OperationLogCodeSupport（解析 SpEL 模板）
    → LogUnifiedProcessingSupport
    → ILogSaveService（DefaultLogSaveServiceImpl）
    → ILogSaveFeign → bedrock-log 微服务
    → 写入 bedrock_log_operation 表
```

`LogOperation` 主要字段：`type`、`subType`、`action`（解析后的日志内容）、`extra`、`userName`、`duration`、`method`、`requestParam`、`tenantId`、`remoteIp` 等。

---

## 注意事项

1. **注解加在 Controller 方法上**：bedrock-cloud 项目统一在 Controller 层标注，Service 层用 `LogRecordContext` 补充变量
2. **同类内部调用不触发 AOP**：操作日志注解必须标注在对外暴露的 Controller 方法上
3. **condition 为空时默认记录**：无论成功失败都会尝试记录
4. **fail 为空时不记录失败日志**：仅 success 模板在成功时生效
5. **bedrock-log 服务必须可用**：否则 Feign 调用失败，操作日志无法入库（请求日志不受影响，走 slf4j 本地输出）
