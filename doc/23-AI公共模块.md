# AI 公共模块 (bedrock-common-ai)

## 概述

`bedrock-common-ai` 基于 **Spring AI**，为业务模块（如 `bedrock-cloud` 的 `bedrock-ai`）提供统一的 AI 基础设施，本身**不包含**业务落库与租户逻辑。

核心能力：

1. **多厂商模型工厂**：Chat / Embedding / Image / Speech 等，按平台 SPI 扩展
2. **向量库工厂**：Redis / Milvus / Elasticsearch / 本地 Simple
3. **ChatClient Advisor 链**：历史记忆、知识库检索、提示词增强、Token 统计（SPI 由业务实现）
4. **工具与 MCP**：`@ToolProvider` 本地工具 + 动态 MCP 客户端

自动配置：`org.bedrock.common.ai.config.AiAutoConfiguration`（经 `bedrock-common-spi` 写入 Boot imports）。

## 快速开始

### Maven 引入

```xml
<dependency>
    <groupId>org.bedrock</groupId>
    <artifactId>bedrock-common-ai</artifactId>
</dependency>
```

向量库后端除 **Simple** 外为 **optional**，按需额外引入：

```xml
<!-- Redis Stack（需 RediSearch + RedisJSON） -->
<dependency>
    <groupId>org.springframework.ai</groupId>
    <artifactId>spring-ai-redis-store</artifactId>
</dependency>
<!-- 或 spring-ai-milvus-store / spring-ai-elasticsearch-store -->
```

未引入对应 jar 时，该后端的 `VectorStoreBuilder` **不会注册**，工厂跳过、启动不报错。

### 自动装配 Bean

| Bean | 默认实现 | 说明 |
|------|----------|------|
| `AiModelFactory` | `DefaultAiModelFactoryImpl` | 模型创建与缓存 |
| `VectorStoreFactory` | `DefaultVectorStoreFactoryImpl` | 向量库创建与缓存 |
| `ToolManager` | 同名 | 扫描 `@ToolProvider` |
| `McpManager` | 同名（`destroyMethod=close`） | 动态 MCP |

均可 `@ConditionalOnMissingBean` 覆盖。

## 模型工厂 AiModelFactory

### 用法

```java
@Autowired
private AiModelFactory aiModelFactory;

ChatModel chatModel = aiModelFactory.getChatModel(new ChatModelCreateParam(
    id, AiPlatformEnum.DEEP_SEEK, apiKey, baseUrl /* ... */
));
EmbeddingModel embedding = aiModelFactory.getEmbeddingModel(/* EmbeddingModelCreateParam */);
```

同类还有 Image / Speech 等 `get*` / `create*` / `remove*`。缓存 key 为各 `*CreateParam.id()`。

### 平台枚举 `AiPlatformEnum`

支持 DeepSeek、DashScope、MiniMax、Moonshot、智谱、混元、星火、百川、硅基流动、Anthropic、Azure OpenAI、Gemini、OpenAI、Mistral、Ollama、Cohere、xAI 等（以枚举源码为准）。

### 扩展新平台

1. 实现 `AiModelBuilder`，`getAiPlatformEnum()` 返回对应平台
2. 类上标注 `@AutoService(AiModelBuilder.class)`（见 [SPI 扩展](./18-SPI扩展.md)）
3. 编译后自动进入 `META-INF/services/...AiModelBuilder`

## 向量库工厂 VectorStoreFactory

### 用法

```java
Map<String, Class<?>> metadataFieldTypes = Map.of(
    "knowledgeId", String.class,
    "docId", String.class,
    "chunkId", String.class
);

VectorStoreCreateParam param = new VectorStoreCreateParam(
    cacheId,
    VectorStoreEnum.REDIS,
    embeddingModel,
    indexName,          // databaseName → Redis indexName
    keyPrefix,          // collectionName → Redis prefix
    embeddingDimension,
    new VectorStoreCreateParam.VectorStoreConnectionParam(host, port, user, pwd),
    Map.of(),           // 扩展 params
    metadataFieldTypes  // 可过滤 metadata：字段名 → Java 类型
);
VectorStore store = vectorStoreFactory.getVectorStore(param);
```

兼容构造：不传 `params` / `metadataFieldTypes` 时默认为空 Map。

### 后端对比

| `VectorStoreEnum` | Builder | 依赖 | 是否消费 `metadataFieldTypes` |
|-------------------|---------|------|-------------------------------|
| `REDIS` | `RedisVectorStoreBuilder` | optional redis-store | **是**（建索引必须声明） |
| `MILVUS` | `MilvusVectorStoreBuilder` | optional milvus-store | 否（metadata 默认 JSON，过滤走 JSON path） |
| `ELASTICSEARCH` | `ElasticsearchVectorStoreBuilder` | optional es-store | 否（动态 mapping，过滤转 `metadata.xxx`） |
| `SIMPLE` | `SimpleVectorStoreBuilder` | 无 | 否（内存按 Document metadata 过滤） |

`removeVectorStore(id)` 会触发 `VectorStorePersistenceRegistry` 清理（如 Simple 的定时持久化任务）。

### Redis：`metadataFieldTypes`（重要）

RediSearch 建索引时必须声明可过滤字段，否则：

| 异常 | 来源 | 含义 |
|------|------|------|
| `Not allowed filter identifier name: knowledgeId` | Spring AI 客户端 | Builder 未注册可过滤字段 |
| `SEARCH_SYNTAX Unknown field ... near knowledgeId` | Redis 服务端 | **已有索引** schema 中无该字段 |

`RedisVectorStoreBuilder` 按 Java 类型映射：

| Java 类型 | Redis MetadataField |
|-----------|---------------------|
| `String` / `CharSequence` | `tag` |
| `Number` 子类 | `numeric` |
| 其它 | `text` |

业务侧可统一传入 `metadataFieldTypes`；Milvus / ES / Simple 创建时忽略即可。

> 索引若在声明字段前已创建：需 `FT.DROPINDEX <indexName>` 或更换 `indexName` 后重建，并重新入库向量。仅改代码不会升级旧索引。

## Advisor 链

本模块提供 **Advisor 实现**；持久化 / 检索 / 增强 / 落库通过 **SPI 接口** 由业务实现并注入。

### 推荐顺序（order 越小越靠前）

相对 `Advisor.DEFAULT_CHAT_MEMORY_PRECEDENCE_ORDER`：

```
ChatHistoryAdvisor              // 默认 -200
  → KnowledgeRetrievalAdvisor   // 默认 -350（更靠前，先检索）
  → PromptAugmentationAdvisor   // 默认 -300
  → ToolCallAdvisor             // Spring AI 自带，不在本模块
  → TokenUsageStatisticsAdvisor
```

实际以各 Advisor Builder 配置的 `order` 为准。

### 对照表

| Advisor | SPI | 作用 |
|---------|-----|------|
| `ChatHistoryAdvisor` | `ChatHistoryStore` | 加载历史、预插入 user/assistant、回填/回滚；支持 tool 与 reasoning |
| `KnowledgeRetrievalAdvisor` | `KnowledgeRetriever` | 向量召回，结果写入 context，**不改** prompt |
| `PromptAugmentationAdvisor` | `PromptAugmenter` | 读检索结果等，决定是否模板改写 UserMessage |
| `TokenUsageStatisticsAdvisor` | `TokenUsageRecorder` | 同步/流式 Token 与耗时统计 |

### 常用 context 键

| 常量位置 | 键 | 说明 |
|----------|----|------|
| `ChatHistoryStore` | `CONVERSATION_ID` / `MAX_MESSAGES` | 会话与条数 |
| `ChatHistoryStore` | `USER_MESSAGE_ID` / `ASSISTANT_MESSAGE_ID` | 预插入后的消息 ID |
| `KnowledgeRetriever` | `KNOWLEDGE_RETRIEVED_DOCUMENTS` | 召回文档列表 |
| `PromptAugmenter` | `QA_CONTEXT_ORIGINAL_USER_QUERY` | 增强前原始用户问题 |

### PromptAugmenter.AugmentResult

```java
record AugmentResult(boolean applyUserTemplate, String contextText) {
    // applyUserTemplate=true：Advisor 用 {context}/{query} 模板改写 UserMessage
    // applyUserTemplate=false：业务已自行改写消息列表，跳过模板
}

new AugmentResult(ragText);     // 等价于 applyUserTemplate=true
new AugmentResult();            // applyUserTemplate=false，跳过模板改写
new AugmentResult(false, text); // 显式跳过模板
```

典型场景：附件已拼进 UserMessage、且不希望再套 RAG 模板时，返回 `new AugmentResult()`。

### ChatEntry.media

`ChatHistoryStore.ChatEntry` 支持 `List<Media> media`（仅内存 / 历史还原，不落库）。7 参构造兼容旧调用（`media` 为空列表）。

## 工具 @ToolProvider 与 ToolManager

```java
@Component
@ToolProvider(name = "currentUser", label = "当前用户", kind = ToolProvider.Kind.METHOD)
public class CurrentUserToolFunction {

    @Tool(description = "获取当前登录用户信息")
    public String currentUser() {
        // ...
    }
}
```

| Kind | 行为 |
|------|------|
| `FUNCTION` | `ToolCallbackResolver.resolve(beanName)` |
| `METHOD` | 扫描 Bean 上 `@Tool` 方法 |

```java
List<ToolCallback> callbacks = toolManager.getCallbacks("currentUser");
```

## MCP：McpManager

动态注册远程 MCP 工具（SSE / Streamable HTTP / STDIO），再按 registrationId 取 `ToolCallback`：

```java
mcpManager.register(registrationId, mcpClientParameters);
List<ToolCallback> tools = mcpManager.getCallbacks(registrationId);
```

应用关闭时 `close()` 释放客户端。

## 与 bedrock-ai 的典型集成

| 业务组件 | 使用的 common-ai 能力 |
|----------|----------------------|
| `AiConfiguration` / `AiChatKit` | 组装 Advisor 链 + ToolCallAdvisor |
| `AiModelServiceImpl` | `AiModelFactory` |
| `AiKnowledgeServiceImpl` | `VectorStoreFactory` + `metadataFieldTypes` |
| `AiKnowledgeRetrieval` | `KnowledgeRetriever` |
| `AiPromptAugmenter` | `PromptAugmenter` / `AugmentResult` |
| `AiChatMessageServiceImpl` | `ChatHistoryStore` |
| `AiTokenUsageServiceImpl` | `TokenUsageRecorder` |
| `AiMcpServiceImpl` | `McpManager` |

职责划分：

- **公共模块**：工厂、Advisor 骨架、SPI 契约
- **业务模块**：密钥与模型配置、知识库/向量库配置、消息与 Token 落库、具体检索与增强策略

## 注意事项

1. **Builder SPI** 用 `@AutoService`；**Advisor SPI**（Store / Retriever / Augmenter / Recorder）用 Spring Bean 注入，机制不同
2. Redis 过滤字段必须在建索引时声明；改声明后旧索引不会自动升级
3. `ToolCallAdvisor` 会二次走 Advisor 链，业务增强需防重复（增强标记 / `AugmentResult`）
4. optional 向量库依赖未引入时，对应 `VectorStoreEnum` 不可用
5. Simple 向量库存于本地磁盘，不适合多实例共享
