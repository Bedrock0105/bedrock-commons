# 认证授权 (Auth)

## 概述

认证授权分为两个模块：

| 模块 | 职责 |
|------|------|
| `bedrock-common-auth` | JWT 工具、当前用户上下文（`AuthUtil`） |
| `bedrock-common-authentication` | OAuth 风格登录端点（`POST /oauth/token`）、Token 签发 |

配合 `bedrock-common-security` 提供接口级权限校验（`@PrePermissionCheck`）。

---

## 快速开始

微服务项目通过 `bedrock-common-cloud` 间接引入，无需单独配置。

### 获取当前用户

```java
Long userId = AuthUtil.getUserId();
String tenantId = AuthUtil.getTenantId();
String nickname = AuthUtil.getNickname();
List<Long> roleIds = AuthUtil.getRoleIds();
boolean isAdmin = AuthUtil.isAdmin();
boolean isAdministrator = AuthUtil.isAdministrator();
```

`AuthUtil` 从请求头 `Authorization: Bearer {token}` 解析 JWT，缓存到 ThreadLocal，请求结束自动清理。

---

## 配置

### bedrock.authentication.*（JWT 签名）

```yaml
bedrock:
  authentication:
    secret-key: your-secret-key-at-least-32-chars  # 必填，≥32 位
    jwt-iss: github                                 # JWT issuer
    jwt-subject: github.com                         # JWT subject
```

> Token 过期时间不在此配置，由数据库 `bedrock_client` 表的 `access_token_validity` / `refresh_token_validity` 决定。

### bedrock.security.*（登录拦截，默认关闭）

```yaml
bedrock:
  security:
    enabled: false           # 开启后未登录请求返回 401
    ignore-urls:
      - /doc.html
      - /webjars/**
      - /v3/api-docs/**
```

## 登录流程

### 1. 获取 Token

```http
POST /oauth/token
Authorization: Basic base64(clientId:clientSecret)
Content-Type: application/x-www-form-urlencoded

grant_type=password&username=admin&password=123456
```

支持的 grant_type：`password`、`refresh_token`

### 2. 响应

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {
    "accessToken": "eyJ...",
    "refreshToken": "eyJ...",
    "tokenType": "Bearer",
    "expiresIn": 3600
  }
}
```

### 3. 携带 Token 访问接口

```http
GET /admin/info
Authorization: Bearer eyJ...
X-Tenant-Id: 000000
```

## JwtUtil API

```java
// 创建 Token
String token = JwtUtil.createToken(tokenId, claims, expireSeconds);

// 解析
Claims claims = JwtUtil.parsePayload(token);   // 完整 claims
String id = JwtUtil.parseId(token);             // tokenId
Object value = JwtUtil.parseClaim(token, "userId");
```

## 扩展点

### 1. 实现 UserDetailsService

```java
@Bean
public UserDetailsService userDetailsService(IAdminClient adminClient) {
    return new UserDetailsServiceImpl(adminClient);
}
```

接口方法：`UserDetails loadUserByUsername(String username, OauthTokenParams params)`

### 2. 实现 TokenEnhancerHandler

向 JWT claims 写入自定义字段（userId、tenantId、roleIds 等）：

```java
@Bean
public TokenEnhancerHandler tokenEnhancerHandler() {
    return new TokenParamTokenEnhancerHandler();
}
```

参考 `bedrock-cloud/bedrock-auth/.../AuthConfiguration.java`

## JWT Claims 约定

| Key | 说明 |
|-----|------|
| `userId` | 用户 ID |
| `username` | 用户名 |
| `tenantId` | 租户 ID |
| `roleIds` | 角色 ID 列表 |
| `roleAlias` | 角色别名列表 |

## 网关鉴权

`bedrock-gateway` 的 `AuthorizeFilter` 使用 `JwtUtil.parsePayload(token)` 校验 Token，无效返回 401。

---

## 密码加密

默认 `PasswordEncoder` 算法：`MD5(SHA512(SHA1(pwd)) + pwd)`，非 BCrypt。

业务层使用 `PasswordUtil.encryptionPassword(password)` 加密存储。

## 注意事项

1. 生产环境必须修改 `secret-key`，长度 ≥ 32 位
2. 登出目前仅记录日志，无 Token 黑名单机制
3. 权限校验使用 `@PrePermissionCheck`，非 Spring Security 的 `@PreAuthorize`
4. Token 传输 Header 名固定为 `Authorization`，前缀 `Bearer`
